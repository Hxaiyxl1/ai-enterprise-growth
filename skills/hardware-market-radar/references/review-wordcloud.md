# 竞品评价词云与口碑拆解

## 一、先解决数据来源

官方旗舰店评价（京东/天猫/抖音商城）几乎都需登录态。已知不可用的路径（2026-11 实测）：

- 京东评价接口 `club.jd.com/comment/productPageComments.action` → **HTTP 444 Forbidden**
- 京东搜索页 → 跳「京东验证」人机校验
- 京东商品详情页 → 可读，但评价正文由异步接口加载，页面里没有
- 淘宝 / 天猫 / 1688 商品页与评价 → 登录墙
- 苏宁 → 可读，但通常没有工业品类目
- 什么值得买 / 慢慢买 → 搜索空壳或页面失效

因此评价正文只能由用户导出，或由用户提供截图。**不得用官网案例、公众号好评、宣传稿代替客户评价**——那是营销素材。

先向用户要清楚：哪几家、哪个渠道、每家多少条、含多少中差评。机器人行业的评价主要在京东工业/天猫官方旗舰店、厂商官网案例、行业社群与展会问卷；前三类里只有旗舰店评价算「官方客户评价」。

## 二、取样规则（决定结论硬度）

1. 每家 **≥30 条**，50–80 条更好；低于 30 条只给方向，不做品牌口碑结论。
2. 尽量覆盖 1–3 星评价。低星占比低于 15% 时标明覆盖有限，保留原样本分布，避免对负面关注点做强结论。
3. 按"推荐排序"取，不要按"追评"或"晒图"筛，会带偏样本。
4. 正文原样，不清洗；口语、错别字、表情保留。
5. 追评单独一行或在正文标记，算独立一条。
6. **不要昵称、订单号、电话**——不采集个人信息。

## 三、字段

`品牌｜渠道｜店铺/账号｜商品型号｜规格｜评分星级｜评价时间｜评价正文｜是否追评｜评价ID｜商品链接｜证据状态`

品牌列做归一化（"优傲""UR""Universal Robots" → 同一家；"节卡""JAKA" → 同一家；"越疆""Dobot" → 同一家）。三家放同一个文件即可。

## 四、执行

```bash
python scripts/build_review_cloud.py <评价表.csv>
```

依赖 `jieba`（`pip install jieba`）。不需要 wordcloud / matplotlib / PIL——脚本自绘 SVG。

产出：
- `词云_竞品对比.html`：三张词云 + 关注点矩阵 + 正负原话摘录
- `词频汇总.csv`、`关注点矩阵.csv`、`明细摘录.csv`

## 五、脚本内部口径（复用时别改坏）

- **分词**：jieba，去 1 字词、数字、停用词；停用词表含「质量/产品/不错/满意」这类无区分度的词，否则词云会全是好评套话。
- **极性判定**：**星级优先**（≤3 星负、≥4 星正），无星级才用词面计数。词面计数前先剔除「没问题/差不多/不错/误差小」等否定式，否则会把「过检没问题」判成负面。
- **关注点**：11 类规则映射，按机器人采购视角——精度与稳定性、负载与节拍、易用与编程、做工与耐用、价格与性价比、发货与物流、客服与响应、部署与集成、售后与保修、培训与交付、合规与认证。换行业直接改脚本 `TOPICS` 的关键词表，不要改判定逻辑。
- **词云排布**：阿基米德螺旋 + 矩形碰撞检测，按字符宽度精确估宽，自动试 k=1.0~1.72 的缩放系数直到铺满画布。同系列多看几次，避免文字重叠。

## 六、怎么读、怎么写结论

- 样本量 <30 只作方向参考，外推品牌口碑属越界。
- 关注点矩阵看的是**结构性差异**：同一维度两家提及率差 2 倍以上才算差异，1 条之差不算。
- 负面原话优先于负面计数：客户具体抱怨什么，比"负面占比 12%"更有用。
- 词云只呈现"在说什么"，不呈现"说得好不好"，好坏必须回到星级与摘录。
- 报告里写清：样本数、渠道、时间窗、中差评占比、采集方式（用户导出）。

## 七、交付话术

图上必须标注「样本 N 条 / 中差评占比 X% / 数据由使用者从官方旗舰店导出」。缺一句就容易被当成全量口碑。
